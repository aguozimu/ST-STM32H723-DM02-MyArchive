# 麦轮底盘惯导位置闭环第一版设计说明

## 1. 文档目的

本文用于指导本工程第一版麦克纳姆轮底盘位置闭环的设计、编码、调试和验收。

第一版的目标不是一次完成完整的惯性导航系统或高阶 ESKF，而是优先建立一条结构正确、可观测、可标定、可逐步扩展的底盘定位与位置控制链路：

1. 使用四轮电机编码器建立二维轮式里程计；
2. 使用 BMI088 与现有 VQF 提供姿态、去偏角速度和辅助动态信息；
3. 融合轮式里程计与 IMU 的航向增量，输出连续的 `x / y / yaw` 位姿；
4. 用位置和航向外环产生 `vx / vy / wz` 速度指令；
5. 复用现有麦轮逆运动学，将底盘速度指令转换成四轮电机速度指令；
6. 为后续打滑检测、EKF/ESKF 和视觉/UWB 等绝对定位观测保留接口。

本文对应“第一版”实现。第一版应先保证坐标、单位、时序和数据有效性正确，再进行滤波和控制参数优化。

---

## 2. 第一版总体结论

### 2.1 推荐定位方案

第一版采用以下分工：

- 四轮编码器里程计负责平面速度和位移的主要估计；
- BMI088 陀螺仪负责短时航向变化和角速度估计；
- VQF 提供 Roll、Pitch、Yaw、四元数以及陀螺仪零偏估计；
- 加速度计第一版主要用于姿态修正、静止/异常辅助判断和后续打滑检测；
- 不使用加速度二次积分作为 `x / y` 位置的主要来源；
- 没有绝对位置传感器时，输出属于局部相对位姿，长期仍会漂移。

数据链路如下：

```text
BMI088 gyro/accel
        |
        +--> VQF 姿态与角速度 ------+
                                      |
四轮编码器位置/速度                  |
        |                             v
        +--> 麦轮正运动学 ------> 2D 位姿融合
                                  x, y, yaw
                                      |
目标位姿 x*, y*, yaw*                 |
        |                             v
        +--------------------> 位置/航向外环
                                vx*, vy*, wz*
                                      |
                                麦轮逆运动学
                                      |
                             四轮电机速度控制
```

### 2.2 为什么不使用纯 IMU 双积分定位

加速度计存在零偏、噪声、温漂、安装误差和底盘振动。很小的恒定加速度误差也会快速积累为明显的位置误差：

```text
position_error = 0.5 * acceleration_bias * time^2
```

例如加速度偏差仅为 `0.05 m/s^2`，20 秒后的理论位置误差约为：

```text
0.5 * 0.05 * 20^2 = 10 m
```

麦轮还会产生明显的滚子振动、横向滑移和地面冲击，因此纯 IMU 双积分不能作为第一版位置闭环的反馈来源。

### 2.3 第一版能力边界

第一版预期可以实现：

- 在平整、摩擦条件较稳定的地面上进行局部坐标系位置闭环；
- 从启动点出发执行短距离直线、横移、旋转和组合运动；
- 在不严重打滑时获得连续的相对位姿；
- 支持目标点保持和简单的点到点移动；
- 为后续轨迹规划和绝对定位融合提供统一状态。

第一版不能保证：

- 长时间运行后仍保持绝对位置准确；
- 严重打滑、碰撞、悬空或地面不平时位置不漂移；
- 没有磁力计或外部航向观测时获得长期无漂移的绝对 Yaw；
- 回到同一物理点时始终获得完全相同的 `x / y / yaw`；
- 用滤波算法消除缺少绝对观测造成的不可观测误差。

```text
User_File/Application/INS/INS.h
User_File/Application/INS/INS.cpp
User_File/Application/Chassis/ChassisController.h
User_File/Application/Chassis/ChassisController.cpp
```

职责约束：

- `INS` 只负责状态估计，不直接控制电机；

- `Chassis` 负责麦轮运动学、电机配置和轮子反馈封装；
- `InsTask` 负责数据调度，不承载复杂设备协议；
- `Control_Task` 负责控制周期、目标管理、安全状态和速度命令下发；
- `BMI088` 驱动层不应包含底盘位置环、轨迹规划或麦轮运动学。

## 4. 坐标系和单位约定

坐标系和单位必须在编码前固定，禁止不同模块各自解释。

### 4.1 机体系

沿用现有 `Class_Chassis::SetVelocity()` 的定义：

- `+X_body`：底盘向右；
- `+Y_body`：底盘向前；
- `+Z_body`：按右手系确定；
- `+wz`：从上向下观察时逆时针为正；
- 车轮顺序固定为左前、右前、左后、右后。

### 4.2 世界系

第一版定义局部世界坐标系：

- 系统复位位姿时，底盘所在位置为世界系原点；
- 复位时底盘右方为 `+X_world`；
- 复位时底盘前方为 `+Y_world`；
- 复位时朝向为 `yaw = 0`；
- 逆时针旋转时 `yaw` 增大。

这是局部相对坐标，不宣称是 NED、ENU、真北或磁北坐标。

### 4.3 单位

统一使用 SI 单位：

| 物理量 | 单位 |
|---|---|
| 位置、轮半径、底盘尺寸 | `m` |
| 速度 | `m/s` |
| 加速度 | `m/s^2` |
| 角度 | `rad` |
| 角速度 | `rad/s` |
| 电机反馈原始角度 | 接口内部可为 `deg`，进入运动学前转换为 `rad` |
| 电机转速 | 驱动层可为 `RPM`，进入运动学前转换为 `rad/s` 或轮缘 `m/s` |
| 时间戳 | `us`，积分时转换成 `s` |

禁止出现以下情况：

- 将 RPM 当作 `m/s` 传给位置控制器；
- 将角度制数值直接传给使用弧度的三角函数；
- 将任务运行周期当作传感器实际采样周期；
- 将 IMU 自身参考系未经安装变换直接当作底盘机体系。

### 4.4 IMU 安装坐标变换

必须通过静态和转动测试确认 BMI088 的 X/Y/Z 轴与底盘坐标系的关系。如果传感器轴与底盘轴不一致，应增加固定安装旋转矩阵：

```text
vector_chassis = R_imu_to_chassis * vector_imu
```

安装变换应集中配置，不能在多个算法中分别交换轴和改符号。

## 5. 麦轮运动学

### 5.1 参数

底盘至少需要以下物理参数：

```cpp
struct Struct_Chassis_Config
{
    float half_length_m;
    float half_width_m;
    float wheel_radius_m;
    float gear_ratio;
};
```

其中：

- `half_length_m`：底盘中心到前/后轮轴的距离；
- `half_width_m`：底盘中心到左/右轮接触中心的距离；
- `wheel_radius_m`：麦轮等效滚动半径，需要实车标定；
- `gear_ratio`：电机转子转速与车轮转速之比。直驱为 1。

令：

```text
R = half_length_m + half_width_m
```

### 5.2 逆运动学

当前工程采用：

```text
v_lf = vy_body + vx_body - R * wz
v_rf = vy_body - vx_body + R * wz
v_lr = vy_body - vx_body - R * wz
v_rr = vy_body + vx_body + R * wz
```

`v_lf` 等表示车轮轮缘线速度。转换成电机 RPM：

```text
motor_rpm = wheel_linear_velocity
          * gear_ratio
          * 60
          / (2 * pi * wheel_radius_m)
```

因此建议在初始化时计算：

```text
speed_to_motor = gear_ratio * 60 / (2 * pi * wheel_radius_m)
```

并明确 `SetVelocity()` 的 `x / y` 始终为 `m/s`，`omega` 始终为 `rad/s`。

### 5.3 正运动学

由四轮轮缘线速度恢复底盘机体系速度：

```text
vx_body = ( v_lf - v_rf - v_lr + v_rr) / 4
vy_body = ( v_lf + v_rf + v_lr + v_rr) / 4
wz_wheel = (-v_lf + v_rf - v_lr + v_rr) / (4 * R)
```

由四轮位移增量恢复底盘位移：

```text
dx_body = ( ds_lf - ds_rf - ds_lr + ds_rr) / 4
dy_body = ( ds_lf + ds_rf + ds_lr + ds_rr) / 4
dyaw_wheel = (-ds_lf + ds_rf - ds_lr + ds_rr) / (4 * R)
```

### 5.4 优先使用位置增量

第一版优先使用电机累计位置差分，而不是仅使用瞬时 RPM 积分：

```text
delta_motor_angle = motor_angle_now - motor_angle_last
delta_wheel_angle = delta_motor_angle / gear_ratio
delta_distance = delta_wheel_angle * wheel_radius_m
```

理由：

- 低速时位置增量通常比速度反馈更稳定；
- 避免速度反馈量化误差持续积分；
- 启停阶段更容易获得完整位移；
- 可以直接检查每周期轮子增量是否合理。

必须验证 `ZDTmotor` 的 `position_deg` 是累计角度还是单圈回绕角度。如果会回绕，则需先进行角度解绕，再计算差分。

## 6. 第一版状态估计

### 6.1 状态结构

建议统一发布以下状态：

```cpp
struct Struct_INS_State
{
    float position_x_m;
    float position_y_m;
    float yaw_rad;

    float velocity_x_world_m_s;
    float velocity_y_world_m_s;

    float velocity_x_body_m_s;
    float velocity_y_body_m_s;
    float yaw_rate_rad_s;

    float accel_x_body_m_s2;
    float accel_y_body_m_s2;

    uint64_t timestamp_us;
    uint32_t sequence;

    bool valid;
    bool wheel_feedback_valid;
    bool imu_valid;
    bool wheel_slip;
};
```

状态发布应满足：

- 消费者一次取得同一版本的完整快照；
- 不能连续读取多个无关联 getter 后假定属于同一帧；
- 使用 `sequence` 或双缓冲保证跨任务读取一致性；
- 状态中必须包含时间戳和有效标志；
- 输入过期后立即置无效，不能无限沿用旧数据。

### 6.2 IMU 输入

现有 BMI088 可提供：

```cpp
BSP_BMI088.Get_Euler_Angle();
BSP_BMI088.Get_Quaternion();
BSP_BMI088.Get_Rotation_Matrix();
BSP_BMI088.Get_Gyro_Body();
BSP_BMI088.Get_Accel_Body();
BSP_BMI088.Get_Accel();
BSP_BMI088.Get_D_T();
BSP_BMI088.Get_VQF_Gyro_Bias();
BSP_BMI088.Get_VQF_Rest_Detected();
```

注意：

- `Get_Euler_Angle()` 顺序为 Yaw、Pitch、Roll，单位 `rad`；
- `Get_Gyro_Body()` 是 VQF 修正后的机体系角速度，单位 `rad/s`；
- `Get_Accel_Body()` 已经去除重力，不要再次减重力；
- `Get_Accel()` 已经去重力并旋转到参考系；
- `Get_D_T()` 是 BMI088 最近一次处理样本的间隔，不应直接作为独立 INS 任务周期；
- VQF 为六轴姿态算法时，Yaw 没有绝对航向约束，长期会漂移；
- 应为 INS 发布一个带统一时间戳的 IMU 快照，避免从多个 getter 拼接不同帧的数据。

### 6.3 轮式里程计输入

建议 `Class_Chassis` 对外提供：

```cpp
struct Struct_Chassis_Wheel_Feedback
{
    float position_rad[CHASSIS_WHEEL_COUNT];
    float velocity_rad_s[CHASSIS_WHEEL_COUNT];
    uint64_t timestamp_us;
    uint32_t sequence;
    uint8_t valid_mask;
};

bool ConfigureOdometryFeedback(uint16_t period_ms);
bool GetWheelFeedback(Struct_Chassis_Wheel_Feedback &feedback) const;
```

`valid_mask` 的每一位对应一个车轮。只有四轮反馈均有效且时间差在允许范围内时，才进行正常正运动学更新。

不要在 `InsTask` 中直接访问 `Class_Chassis` 内部四个 `Class_ZDTMotor` 对象。轮序、减速比、方向和单位转换都应由底盘模块统一处理。

### 6.4 航向融合

第一版使用互补思想融合陀螺仪和轮式旋转增量：

```text
dyaw_gyro = gyro_z * dt
dyaw = alpha * dyaw_gyro + (1 - alpha) * dyaw_wheel
yaw = WrapAngle(yaw + dyaw)
```

初始参数可从以下范围开始：

```text
alpha = 0.95 ~ 0.995
```

解释：

- `alpha` 大：更信任 IMU，短时旋转响应好，但长期受陀螺仪漂移影响；
- `alpha` 小：更信任轮子，容易受打滑和麦轮横向耦合影响；
- 参数必须通过原地旋转和组合运动实测调整；
- 这不是绝对航向校正，轮式里程计本身同样会漂移。

如果确认 VQF Yaw 的零偏处理优于自行积分，也可以使用 VQF Yaw 增量代替 `gyro_z * dt`，但应对 `-pi / +pi` 跳变进行角度差包装。

### 6.5 平移位置积分

将机体系位移旋转到世界系：

```text
dx_world = cos(yaw_mid) * dx_body - sin(yaw_mid) * dy_body
dy_world = sin(yaw_mid) * dx_body + cos(yaw_mid) * dy_body

x += dx_world
y += dy_world
```

推荐使用周期中点航向：

```text
yaw_mid = yaw_previous + 0.5 * dyaw
```

相较于直接使用周期起点或终点航向，中点法在同时平移和旋转时误差更小。

速度可以由本周期位移除以实际时间差得到：

```text
vx_body = dx_body / dt
vy_body = dy_body / dt
```

然后再旋转到世界系。`dt` 必须来自连续反馈的采样时间戳，不能硬编码为 0.01 秒后就完全忽略抖动。

### 6.6 初始化和复位

推荐接口：

```cpp
void Init();
void ResetPose(float x_m, float y_m, float yaw_rad);
Struct_INS_State GetState() const;
```

初始化条件：

1. BMI088 已完成初始化；
2. VQF 输出有效；
3. 四轮反馈均至少成功接收一次；
4. 已保存四轮初始累计角度，避免首次更新出现大位移；
5. 时间戳正常且未过期；
6. 底盘在启动阶段尽量保持静止，使陀螺仪零偏估计稳定。

`ResetPose()` 只重置导航坐标原点，不应清除电机驱动器内部位置，除非调用者明确要求机械回零。

## 7. 位置闭环设计

### 7.1 控制结构

采用三级结构：

```text
轨迹/目标生成
      |
位置和航向外环
      |
vx_body_target / vy_body_target / wz_target
      |
麦轮逆运动学
      |
四轮电机内部速度控制
```

第一版不要从位置误差直接计算四个轮子的 RPM。位置控制与麦轮逆运动学必须分层。

### 7.2 世界系误差转换到机体系

目标误差：

```text
ex_world = target_x - current_x
ey_world = target_y - current_y
eyaw = WrapAngle(target_yaw - current_yaw)
```

转换到底盘机体系：

```text
ex_body =  cos(yaw) * ex_world + sin(yaw) * ey_world
ey_body = -sin(yaw) * ex_world + cos(yaw) * ey_world
```

第一版控制律：

```text
vx_command = kp_x * ex_body
vy_command = kp_y * ey_body
wz_command = kp_yaw * eyaw
```

这里的 `vx_command` 表示向右速度，`vy_command` 表示向前速度。

### 7.3 第一版使用 P 控制

位置外环第一版先使用 P 控制，不急于加入积分项：

- 麦轮受阻或打滑时，积分项容易累积；
- 障碍解除后可能突然输出大速度；
- 静态误差首先应排查轮径、方向、减速比和摩擦问题；
- 加入积分前必须实现输出限幅和抗积分饱和。

如后续需要改善动态响应，可以加入期望速度前馈：

```text
velocity_command = trajectory_velocity_feedforward
                 + Kp * position_error
```

### 7.4 输出限制

控制器必须具备：

- 最大平移速度限制；
- 最大角速度限制；
- 最大平移加速度限制；
- 最大角加速度限制；
- 目标附近减速；
- 位置到达死区；
- 航向到达死区；
- 状态无效时立即停止；
- 电机离线或反馈超时时立即停止；
- 控制任务卡顿或周期异常时立即停止。

二维平移速度推荐按向量模长统一限幅，避免 X/Y 分别限幅后斜向速度变成单轴上限的 `sqrt(2)` 倍：

```text
speed = sqrt(vx^2 + vy^2)
if speed > max_speed:
    scale = max_speed / speed
    vx *= scale
    vy *= scale
```

### 7.5 到达判定

建议同时满足以下条件并持续一定时间才报告到达：

```text
sqrt(ex_world^2 + ey_world^2) < position_tolerance
abs(eyaw) < yaw_tolerance
sqrt(vx_body^2 + vy_body^2) < velocity_tolerance
abs(yaw_rate) < yaw_rate_tolerance
```

避免只根据位置误差判断，否则底盘可能高速穿过目标点时被瞬间判定为到达。

## 8. 任务和数据时序

### 8.1 建议频率

| 模块 | 建议频率 |
|---|---:|
| BMI088 陀螺仪采集和 VQF 更新 | 保持现有约 2 kHz |
| BMI088 加速度更新 | 保持现有约 250 Hz |
| 四轮位置反馈 | 50~100 Hz |
| INS/里程计融合 | 100 Hz 或由完整轮反馈触发 |
| 底盘位置闭环 | 100 Hz |
| 电机速度命令 | 100 Hz 起步，按 ZDT/CAN 能力调整 |

### 8.2 推荐任务职责

`BMI088_Task`：

- 继续处理 BMI088 FIFO；
- 继续执行 VQF；
- 发布带时间戳的最新 IMU 快照；
- 不执行位置闭环。

`InsTask`：

- 等待新的完整轮子反馈或固定 100 Hz 运行；
- 读取同一版本的轮反馈和 IMU 快照；
- 验证时间戳、新鲜度和有效性；
- 计算轮子位移增量；
- 完成航向融合和位姿积分；
- 发布 `Struct_INS_State` 快照。

`Control_Task`：

- 固定周期运行，建议初始为 100 Hz；
- 调用 `Chassis.Process()`；
- 读取最新 INS 状态；
- 执行目标管理、位置/航向控制和限幅；
- 调用 `Chassis.SetVelocity()`；
- 执行超时、安全停止和到达判定。

### 8.3 禁止使用阻塞式运行接口做闭环

现有 `RunForSeconds()` 会在任务中调用 `osDelay()`，适合简单演示，不适合位置闭环。闭环任务应使用：

```cpp
uint32_t next_tick = osKernelGetTickCount();

for (;;)
{
    next_tick += 10U;

    Chassis.Process();
    const Struct_INS_State state = INS.GetState();
    Controller.Update(state);
    Chassis.SetVelocity(vx_command, vy_command, wz_command);

    osDelayUntil(next_tick);
}
```

实际代码应根据 `osKernelGetTickFreq()` 换算周期，不能默认系统 tick 一定是 1 ms。

### 8.4 时间戳要求

- 每个轮子反馈应保留接收时间；
- 完整四轮快照应记录统一发布时刻和各轮数据年龄；
- IMU 快照必须记录其真实采样或解算时间；
- INS 使用输入时间戳计算 `dt`；
- `dt <= 0`、明显过大或时间倒退时拒绝本次积分；
- 数据重复时不得再次积分；
- 任务唤醒标志只能表示“有数据”，不能代替样本队列或序号。

## 10. 数据有效性和安全策略

### 10.1 轮子反馈有效性

以下任一情况出现时，不应继续正常积分：

- 任一车轮离线；
- 任一车轮反馈超时；
- 四轮反馈时间差超过阈值；
- 位置增量超过物理上限；
- 时间戳不递增；
- 电机报告堵转、过流、过温或保护；
- 反馈校验错误连续出现。

在定位输入暂时失效时，可短时间保持最后速度估计用于平滑，但控制输出应尽快降为零；第一版建议直接安全停止，降低系统复杂度。

### 10.2 IMU 有效性

以下情况应将 IMU 判为异常：

- BMI088/VQF 重置计数增加；
- 时间戳异常计数增加；
- 加速度或角速度出现非有限值；
- IMU 数据超过新鲜度阈值；
- 陀螺仪样本间隔明显异常；
- 姿态矩阵或四元数无效。

IMU 短时失效时，可以仅用轮式 `dyaw_wheel` 更新，但应记录降级状态并限制最大速度。

### 10.3 控制安全

以下情况必须停止底盘：

- INS 状态无效；
- 控制周期超时；
- 任一关键电机离线；
- 目标或计算结果为 NaN/Inf；
- 输出超出合理物理范围；
- 外部急停或任务故障；
- 初始化未完成。

停止时优先调用四轮同步停止，避免只停止部分车轮导致底盘突然旋转。

## 11. 第一版打滑处理

第一版不需要立刻实现复杂打滑估计，但必须预留检测标志和降级策略。

### 11.1 角速度残差

```text
residual_wz = abs(wz_wheel - gyro_z)
```

残差持续超过阈值时，可能存在：

- 车轮打滑；
- 轮径或 `R` 参数错误；
- IMU 和底盘坐标轴符号错误；
- 轮反馈时间不同步；
- 陀螺仪偏置或异常。

不能仅凭单帧残差认定打滑。

### 11.2 加速度残差

轮式速度差分得到预测加速度：

```text
ax_wheel = (vx_body_now - vx_body_previous) / dt
ay_wheel = (vy_body_now - vy_body_previous) / dt
```

与低通后的 IMU 线加速度比较：

```text
residual_a = norm(a_wheel - a_imu_body)
```

加速度计容易受麦轮滚子振动和冲击影响，所以需要：

- 低通滤波；
- 连续多帧超阈值；
- 排除碰撞和跳变；
- 结合角速度残差和电机状态共同判断。

### 11.3 第一版降级策略

检测到疑似打滑时：

- 设置 `wheel_slip = true`；
- 限制平移速度与加速度；
- 降低对轮式旋转增量的权重；
- 记录调试数据；
- 严重或持续打滑时停止底盘。

不要在没有绝对位置观测时完全相信 IMU 平移积分来替代轮式位置，否则通常会产生更大误差。

## 12. 参数标定

### 12.1 车轮等效半径

1. 让四轮执行相同的累计角度；
2. 测量底盘直线实际位移；
3. 根据理论位移与实际位移比例修正轮半径；
4. 正向和反向分别测试；
5. 多次取平均。

麦轮的等效半径可能与标称外径不同，应使用实车结果。

### 12.2 旋转几何参数

原地旋转若干圈，比较：

- 轮式里程计计算的角度；
- IMU 计算的角度；
- 人工或外部基准测得的实际角度。

据此标定有效旋转半径 `R_effective`。实际有效值可能不完全等于机械测量的 `half_length + half_width`。

### 12.3 横移比例

麦轮横移滑移通常大于纵向运动。可在第一版后期加入独立比例：

```text
dx_body_corrected = k_lateral * dx_body
dy_body_corrected = k_longitudinal * dy_body
```

但在坐标、极性、轮径和时间戳尚未验证前，不应使用经验比例掩盖基础错误。

### 12.4 IMU 零点和安装

- 启动时静置，检查 `gyro_z` 平均值；
- 检查静止时去重力加速度是否接近零；
- 向右、向前和逆时针运动，检查轴符号；
- 倾斜底盘检查 Roll/Pitch 方向；
- 确认加热器启用状态与加速度/陀螺仪标定参数是否匹配。

## 13. 推荐实现顺序

严格按以下顺序实现和验收，不要一开始同时调定位、融合和位置 PID。

### 阶段 1：统一单位和底盘参数

- 增加轮半径和减速比；
- 明确 `SetVelocity()` 使用 `m/s`、`rad/s`；
- 正确计算 `speed_to_motor`；
- 验证四轮极性和轮序。

验收：分别发出纯向右、纯向前和纯逆时针命令，四轮方向符合运动学定义。

### 阶段 2：取得可靠的四轮反馈

- 配置位置周期反馈；
- 封装完整四轮反馈快照；
- 增加序号、时间戳、有效掩码和超时；
- 确认位置是否回绕；
- 确认反馈方向已经应用电机极性。

验收：手动转动单个轮子，仅对应轮子的累计角度按预期方向变化。

### 阶段 3：纯轮式里程计

- 实现位移增量计算；
- 实现麦轮正运动学；
- 暂时只使用 `dyaw_wheel`；
- 输出并绘制 `x / y / yaw`。

验收：完成直线、横移、原地旋转和矩形路线测试，方向和量级正确。

### 阶段 4：接入 IMU 航向

- 发布一致的 IMU 快照；
- 验证机体系轴映射；
- 使用 `gyro_z` 或 VQF Yaw 增量；
- 实现互补融合；
- 处理角度包装和时间异常。

验收：原地旋转和边走边转时航向连续，无 `2*pi` 跳变，停止后漂移速度可接受。

### 阶段 5：位置闭环

- 新建位置控制器；
- 将世界系位置误差转换到机体系；
- 首先使用 P 控制；
- 加入速度、加速度和角速度限制；
- 实现到达判定和异常停止。

验收：低速执行单轴目标，再执行组合目标；误差收敛，目标附近无明显振荡。

### 阶段 6：标定和打滑检测

- 标定轮径、旋转半径和横移比例；
- 记录轮式与 IMU 残差；
- 加入持续多帧的打滑判定；
- 增加打滑时降速或停止策略。

验收：不同速度和方向下误差可重复；轻微打滑不会立即引发错误动作，严重打滑能进入降级状态。

## 14. 调试遥测要求

至少记录以下变量，否则很难区分运动学、传感器和控制器问题：

### 14.1 原始反馈

- 四轮累计角度；
- 四轮角速度；

- VQF Yaw；

- `dyaw_gyro`；
- 融合后的 `dyaw`；
- `dt`；
- 打滑残差。

### 14.3 状态与控制

- `x / y / yaw`；
- `vx_body / vy_body / wz`；

调试输出不得阻塞高优先级任务。建议状态保存到调试镜像，由低优先级通信任务异步发送。

## 15. 测试与验收清单

### 15.1 静态测试

- [ ] 静止时四轮增量为零或接近零；
- [ ] 静止时 `gyro_z` 经过收敛后接近零；

### 15.2 手动推动测试

- [ ] 向前推动时 `y` 增加，`x` 基本不变；
- [ ] 向右推动时 `x` 增加，`y` 基本不变；
- [ ] 逆时针旋转时 `yaw` 增加；
- [ ] 顺时针旋转时 `yaw` 减少；
- [ ] 旋转 90 度后向前推动，世界系位移方向正确；
- [ ] 角度跨越 `-pi / +pi` 时输出连续。

### 15.3 开环运动测试

- [ ] 低速向前 1 m，测量里程计误差；
- [ ] 低速横移 1 m，测量里程计误差；
- [ ] 原地旋转 360 度，测量航向误差；
- [ ] 正反方向误差基本对称；
- [ ] 不同速度下比例误差可重复；
- [ ] 矩形路线的最终闭合误差有记录。

### 15.4 闭环测试

- [ ] 仅控制 X，目标误差能稳定收敛；
- [ ] 仅控制 Y，目标误差能稳定收敛；
- [ ] 仅控制 Yaw，目标误差能稳定收敛；
- [ ] 组合目标可以同时收敛；
- [ ] 接近目标时不会持续振荡；
- [ ] 速度和加速度不超过限制；
- [ ] 高速穿过目标时不会误判为已到达；
- [ ] 传感器失效时四轮同步停止；
- [ ] 目标更新时没有突变到危险输出。

### 15.5 建议验收指标

第一版指标应根据底盘尺寸、地面和任务需求最终确定。初始调试可先采用相对宽松指标：

- 1 m 纵向运动误差小于 5%；
- 1 m 横向运动误差小于 10%；
- 原地旋转 360 度误差小于 5 度；
- 目标保持时无持续明显振荡；
- 任一关键反馈超时后 100 ms 内停止输出；
- 连续运行过程中不出现 NaN、时间倒退或位姿突跳。

这些只是第一阶段参考值，不代表最终产品指标。

## 16. 常见错误

1. 直接对 `Get_Accel()` 二次积分并把结果作为唯一位置反馈；
2. 对 `Get_Accel_Body()` 再减一次重力；
3. 将 RPM、轮角速度和轮缘线速度混用；
4. 将度和弧度混用；
5. 用固定任务周期代替传感器时间戳；
6. 多次收到同一反馈时重复积分；
7. 四个轮子反馈不在同一时间附近仍直接做正运动学；
8. 忽略电机极性、轮序和麦轮滚子安装方向；
9. 使用位置 PID 直接输出四轮速度而跳过底盘速度层；
10. 一开始加入较大积分项，掩盖机械参数和单位错误；
11. 使用 `RunForSeconds()` 的阻塞流程实现闭环；
12. 只判断位置误差，不判断当前速度就报告到达；
13. 发生打滑时完全改用 IMU 平移双积分；
14. 把 VQF Yaw 当作长期无漂移的绝对航向；
15. 没有状态有效标志和超时保护仍继续下发速度。

## 17. 后续升级方向

第一版完成后，可按需求逐步升级：

### 17.1 二维 EKF/ESKF

可选状态：

```text
[x, y, yaw, vx, vy, gyro_bias_z]
```

预测输入：

```text
gyro_z, accel_x, accel_y
```

观测：

```text
wheel_vx_body, wheel_vy_body, wheel_wz
absolute_x, absolute_y, absolute_yaw
```

在没有绝对观测时，EKF/ESKF 只能改善噪声分配和短时估计，不能从根本上消除长期漂移。

### 17.2 绝对位置观测

需要长期重复到点时，建议加入至少一种：

- 相机与 AprilTag；
- 激光雷达定位；
- UWB；
- 室外 GNSS/RTK；
- 地面光流；
- 固定视觉标志点。

### 17.3 轨迹规划

位置环稳定后加入：

- 梯形速度规划；
- S 曲线加减速；
- 直线/圆弧轨迹；
- 轨迹速度和加速度前馈；
- 横向误差与航向误差联合控制。

## 18. 第一版完成定义

满足以下条件时，才认为第一版完成：

1. 坐标系、单位、轮序和极性有明确且经过实车验证的定义；
2. 四轮位置反馈可持续、带时间戳且能检测超时；
3. 已实现麦轮正运动学和局部二维里程计；
4. 已使用 BMI088 角速度对航向进行融合；
5. 已发布一致、带序号和有效标志的 INS 状态快照；
6. 已将 `Control_Task` 改造成非阻塞固定周期闭环；
7. 已实现位置/航向外环、限速、限加速度和到达判定；
8. 任一关键数据失效时能够安全停止；
9. 已完成前进、横移、旋转、组合移动和闭环到点测试；
10. 关键输入、中间状态和输出均可遥测、记录和复现；
11. 已记录轮径、旋转半径、横移比例和控制参数的标定值；
12. 已明确第一版的实测误差和适用边界。

第一版的核心评价标准是“链路正确、行为可解释、异常可停止、误差可测量”，而不是依靠复杂滤波器在基础参数尚未验证时获得表面平滑的数据。
