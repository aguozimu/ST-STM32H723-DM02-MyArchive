# 麦轮底盘惯导位置闭环第一版设计说明

> 修订日期：2026-09-20  
> 核对依据：当前工程源码与《ZDT_X42S 第二代闭环步进电机用户手册 V1.0.5（260527）》  
> 本文中的“现有接口”指已经存在于工程中的实现；“建议新增”表示后续编码仍需补充。

## 1. 文档目的

本文用于指导本工程第一版麦克纳姆轮底盘位置闭环的设计、编码、调试和验收。

第一版的目标不是一次完成完整的惯性导航系统或高阶 ESKF，而是优先建立一条结构正确、可观测、可标定、可逐步扩展的底盘定位与位置控制链路：

1. 使用四轮电机编码器建立二维轮式里程计；
2. 使用 BMI088 与现有 VQF 提供姿态、去偏角速度和辅助动态信息；
3. 融合轮式里程计与 IMU 的航向增量，输出连续的 `x / y / yaw` 位姿；
4. 用位置和航向外环产生 `vx / vy / wz` 速度指令；
5. 复用现有麦轮逆运动学，将底盘速度指令转换成四轮电机速度指令；
6. 为后续打滑检测、EKF/ESKF 和视觉/UWB 等绝对定位观测保留接口。

本文对应“第一版”实现。第一版应先保证坐标、单位、时序和数据有效性正确，再进行滤波和控制参数优化。

## 2. 第一版总体结论

### 2.1 推荐定位方案

第一版采用以下分工：

- 四轮编码器里程计负责平面速度和位移的主要估计；
- BMI088 陀螺仪负责短时航向变化和角速度估计；
- VQF 提供 Roll、Pitch、Yaw、四元数以及陀螺仪零偏估计；
- 加速度计第一版主要用于姿态修正、静止/异常辅助判断和后续打滑检测；
- 不使用加速度二次积分作为 `x / y` 位置的主要来源；
- 没有绝对位置传感器时，输出属于局部相对位姿，长期仍会漂移。

数据链路如下：

```text
BMI088 gyro/accel
        |
        +--> VQF 姿态与角速度 ------+
                                      |
四轮编码器位置/速度                  |
        |                             v
        +--> 麦轮正运动学 ------> 2D 位姿融合
                                  x, y, yaw
                                      |
目标位姿 x*, y*, yaw*                 |
        |                             v
        +--------------------> 位置/航向外环
                                vx*, vy*, wz*
                                      |
                                麦轮逆运动学
                                      |
                             四轮电机速度控制
```

### 2.2 为什么不使用纯 IMU 双积分定位

加速度计存在零偏、噪声、温漂、安装误差和底盘振动。很小的恒定加速度误差也会快速积累为明显的位置误差：

```text
position_error = 0.5 * acceleration_bias * time^2
```

例如加速度偏差仅为 `0.05 m/s^2`，20 秒后的理论位置误差约为：

```text
0.5 * 0.05 * 20^2 = 10 m
```

麦轮还会产生明显的滚子振动、横向滑移和地面冲击，因此纯 IMU 双积分不能作为第一版位置闭环的反馈来源。

### 2.3 第一版能力边界

第一版预期可以实现：

- 在平整、摩擦条件较稳定的地面上进行局部坐标系位置闭环；
- 从启动点出发执行短距离直线、横移、旋转和组合运动；
- 在不严重打滑时获得连续的相对位姿；
- 支持目标点保持和简单的点到点移动；
- 为后续轨迹规划和绝对定位融合提供统一状态。

第一版不能保证：

- 长时间运行后仍保持绝对位置准确；
- 严重打滑、碰撞、悬空或地面不平时位置不漂移；
- 没有磁力计或外部航向观测时获得长期无漂移的绝对 Yaw；
- 回到同一物理点时始终获得完全相同的 `x / y / yaw`；
- 用滤波算法消除缺少绝对观测造成的不可观测误差。

### 3.2 当前工程还缺少的关键接口

虽然 ZDT 底层已经能够解析位置，但第一版里程计仍不能直接开始编码，原因如下：

1. `Class_Chassis::motors[4]` 是私有成员，当前没有四轮反馈聚合接口；
2. `Struct_ZDTMotor_Feedback::last_rx_timestamp_us` 会被任意合法反馈刷新，不是 `0x36` 位置专用时间戳；
3. `Struct_ZDTMotor_Feedback::rx_count` 统计所有功能码，不是位置更新序号；
4. `last_function == 0x36` 只能描述快照时最近一帧，不能保证消费者没有漏过或重复使用位置帧；
5. 当前匿名命名空间中的 `Class_Chassis Chassis` 只在 `Control_Task.cpp` 可见，`InsTask` 无法通过公共接口获取底盘快照；
6. `Ins_Task()` 当前只等待 `0x0001`，工程中没有找到向 `InsTaskHandle` 设置该标志的生产者；
7. 当前 `Control_Task` 使用阻塞式 `RunForSeconds()`，没有形成固定周期闭环；
8. `Struct_Chassis_Config` 尚无轮径和减速比；`speed_to_motor=1.0f` 不能用于以 `m/s` 为输入的闭环。
9. BMI088 已有多个原子 getter，但尚无同一帧的统一 IMU 输出快照、样本时间戳和更新序号；`Get_Calculating_Time()` 是计算耗时，不是样本时间戳；
10. 当前 `Class_Chassis Chassis` 位于 `Control_Task.cpp` 匿名命名空间。整个系统只能保留一个底盘实例，不能在 `InsTask` 再初始化第二套电机对象，否则相同 CAN 回调键会注册失败。

因此建议先补充下列最小接口，再实现 INS：

```cpp
// ZDT 位置字段自己的版本信息，由成功解析 0x36 时更新。
uint64_t position_timestamp_us;
uint32_t position_update_count;
int64_t position_raw_signed;

// Chassis 聚合四轮数据，屏蔽私有 motors[]、轮序、方向和单位细节。
bool ConfigureOdometryFeedback(uint16_t period_ms);
bool StopOdometryFeedback();
bool GetWheelFeedback(Struct_Chassis_Wheel_Feedback &feedback) const;
bool IsInitialized() const;
```

第一版推荐让 `InsTask` 以 100 Hz 固定周期读取 `GetWheelFeedback()`，通过每轮独立的 `position_update_count` 判断是否有新样本。这样不依赖尚未建立的线程标志生产者。后续若需要更低延迟，再由四轮快照发布逻辑通知 `InsTask`。

底盘实例可以移动到 `Chassis.cpp` 并通过 `extern Class_Chassis Chassis` 暴露，也可以在创建任务时把同一实例指针作为任务参数传入。第一版推荐前者以匹配工程中 `BSP_BMI088` 的现有全局设备对象模式，但仍只暴露底盘级公共接口，不暴露内部 `motors[]`。

推荐新增模块：

```text
User_File/Application/INS/INS.h
User_File/Application/INS/INS.cpp
User_File/Application/Chassis/ChassisController.h
User_File/Application/Chassis/ChassisController.cpp
```

职责约束：

- `INS` 只负责状态估计，不直接控制电机；
- `ChassisController` 只负责由目标位姿和当前状态计算速度指令；
- `Chassis` 负责麦轮运动学、电机配置和轮子反馈封装；
- `InsTask` 负责数据调度，不承载复杂设备协议；
- `Control_Task` 负责控制周期、目标管理、安全状态和速度命令下发；
- `BMI088` 驱动层不应包含底盘位置环、轨迹规划或麦轮运动学。

## 4. 坐标系和单位约定

坐标系和单位必须在编码前固定，禁止不同模块各自解释。

### 4.1 机体系

沿用现有 `Class_Chassis::SetVelocity()` 的定义：

- `+X_body`：底盘向右；
- `+Y_body`：底盘向前；
- `+Z_body`：按右手系确定；
- `+wz`：从上向下观察时逆时针为正；
- 车轮顺序固定为左前、右前、左后、右后。

### 4.2 世界系

第一版定义局部世界坐标系：

- 系统复位位姿时，底盘所在位置为世界系原点；
- 复位时底盘右方为 `+X_world`；
- 复位时底盘前方为 `+Y_world`；
- 复位时朝向为 `yaw = 0`；
- 逆时针旋转时 `yaw` 增大。

这是局部相对坐标，不宣称是 NED、ENU、真北或磁北坐标。

### 4.3 单位

统一使用 SI 单位：

| 物理量 | 单位 |
|---|---|
| 位置、轮半径、底盘尺寸 | `m` |
| 速度 | `m/s` |
| 加速度 | `m/s^2` |
| 角度 | `rad` |
| 角速度 | `rad/s` |
| 电机反馈原始角度 | 接口内部可为 `deg`，进入运动学前转换为 `rad` |
| 电机转速 | 驱动层可为 `RPM`，进入运动学前转换为 `rad/s` 或轮缘 `m/s` |
| 时间戳 | `us`，积分时转换成 `s` |

禁止出现以下情况：

- 将 RPM 当作 `m/s` 传给位置控制器；
- 将角度制数值直接传给使用弧度的三角函数；
- 将任务运行周期当作传感器实际采样周期；
- 将 IMU 自身参考系未经安装变换直接当作底盘机体系。

### 4.4 IMU 安装坐标变换

必须通过静态和转动测试确认 BMI088 的 X/Y/Z 轴与底盘坐标系的关系。如果传感器轴与底盘轴不一致，应增加固定安装旋转矩阵：

```text
vector_chassis = R_imu_to_chassis * vector_imu
```

安装变换应集中配置，不能在多个算法中分别交换轴和改符号。

## 5. 麦轮运动学

### 5.1 参数

底盘至少需要以下物理参数：

```cpp
struct Struct_Chassis_Config
{
    float half_length_m;
    float half_width_m;
    float wheel_radius_m;
    float gear_ratio;
};
```

其中：

- `half_length_m`：底盘中心到前/后轮轴的距离；
- `half_width_m`：底盘中心到左/右轮接触中心的距离；
- `wheel_radius_m`：麦轮等效滚动半径，需要实车标定；
- `gear_ratio`：电机转子转速与车轮转速之比。直驱为 1。

令：

```text
R = half_length_m + half_width_m
```

### 5.2 逆运动学

当前工程采用：

```text
v_lf = vy_body + vx_body - R * wz
v_rf = vy_body - vx_body + R * wz
v_lr = vy_body - vx_body - R * wz
v_rr = vy_body + vx_body + R * wz
```

`v_lf` 等表示车轮轮缘线速度。转换成电机 RPM：

```text
motor_rpm = wheel_linear_velocity
          * gear_ratio
          * 60
          / (2 * pi * wheel_radius_m)
```

因此建议在初始化时计算：

```text
speed_to_motor = gear_ratio * 60 / (2 * pi * wheel_radius_m)
```

并明确 `SetVelocity()` 的 `x / y` 始终为 `m/s`，`omega` 始终为 `rad/s`。

### 5.3 正运动学

由四轮轮缘线速度恢复底盘机体系速度：

```text
vx_body = ( v_lf - v_rf - v_lr + v_rr) / 4
vy_body = ( v_lf + v_rf + v_lr + v_rr) / 4
wz_wheel = (-v_lf + v_rf - v_lr + v_rr) / (4 * R)
```

由四轮位移增量恢复底盘位移：

```text
dx_body = ( ds_lf - ds_rf - ds_lr + ds_rr) / 4
dy_body = ( ds_lf + ds_rf + ds_lr + ds_rr) / 4
dyaw_wheel = (-ds_lf + ds_rf - ds_lr + ds_rr) / (4 * R)
```

### 5.4 优先使用位置增量

第一版优先使用电机累计位置的原始整数计数差分，而不是仅使用瞬时 RPM 积分：

```text
delta_position_raw = position_raw_now - position_raw_last
delta_motor_angle = RawToRadians(delta_position_raw)
delta_wheel_angle = delta_motor_angle / gear_ratio
delta_distance = delta_wheel_angle * wheel_radius_m
```

理由：

- 低速时位置增量通常比速度反馈更稳定；
- 避免速度反馈量化误差持续积分；
- 启停阶段更容易获得完整位移；
- 可以直接检查每周期轮子增量是否合理。

必须验证 `ZDTmotor` 的位置反馈是累计角度还是单圈回绕角度。如果会回绕，则需先进行整数解绕，再计算差分。现有 `float position_deg` 适合遥测，但累计值很大后相减会损失小增量精度，因此正式里程计应保留 `0x36` 的带符号原始整数。

## 6. 第一版状态估计

### 6.1 状态结构

建议统一发布以下状态：

```cpp
struct Struct_INS_State
{
    float position_x_m;
    float position_y_m;
    float yaw_rad;

    float velocity_x_world_m_s;
    float velocity_y_world_m_s;

    float velocity_x_body_m_s;
    float velocity_y_body_m_s;
    float yaw_rate_rad_s;

    float accel_x_body_m_s2;
    float accel_y_body_m_s2;

    uint64_t timestamp_us;
    uint32_t sequence;

    bool valid;
    bool wheel_feedback_valid;
    bool imu_valid;
    bool wheel_slip;
};
```

状态发布应满足：

- 消费者一次取得同一版本的完整快照；
- 不能连续读取多个无关联 getter 后假定属于同一帧；
- 使用 `sequence` 或双缓冲保证跨任务读取一致性；
- 状态中必须包含时间戳和有效标志；
- 输入过期后立即置无效，不能无限沿用旧数据。

### 6.2 IMU 输入

现有 BMI088 可提供：

```cpp
BSP_BMI088.Get_Euler_Angle();
BSP_BMI088.Get_Quaternion();
BSP_BMI088.Get_Rotation_Matrix();
BSP_BMI088.Get_Gyro_Body();
BSP_BMI088.Get_Accel_Body();
BSP_BMI088.Get_Accel();
BSP_BMI088.Get_D_T();
BSP_BMI088.Get_VQF_Gyro_Bias();
BSP_BMI088.Get_VQF_Rest_Detected();
```

注意：

- `Get_Euler_Angle()` 顺序为 Yaw、Pitch、Roll，单位 `rad`；
- `Get_Gyro_Body()` 是 VQF 修正后的机体系角速度，单位 `rad/s`；
- `Get_Accel_Body()` 已经去除重力，不要再次减重力；
- `Get_Accel()` 已经去重力并旋转到参考系；
- `Get_D_T()` 是 BMI088 最近一次处理样本的间隔，不应直接作为独立 INS 任务周期；
- VQF 为六轴姿态算法时，Yaw 没有绝对航向约束，长期会漂移；
- 应为 INS 发布一个带统一时间戳的 IMU 快照，避免从多个 getter 拼接不同帧的数据。

### 6.3 轮式里程计输入

建议 `Class_Chassis` 对外提供：

```cpp
struct Struct_Chassis_Wheel_Feedback
{
    int64_t position_raw_signed[CHASSIS_WHEEL_COUNT];
    float position_rad[CHASSIS_WHEEL_COUNT];
    float velocity_rad_s[CHASSIS_WHEEL_COUNT];
    uint64_t position_timestamp_us[CHASSIS_WHEEL_COUNT];
    uint32_t position_update_count[CHASSIS_WHEEL_COUNT];
    uint64_t snapshot_timestamp_us;
    uint32_t sequence;
    uint8_t valid_mask;
    uint8_t fresh_mask;
};

bool ConfigureOdometryFeedback(uint16_t period_ms);
bool StopOdometryFeedback();
bool GetWheelFeedback(Struct_Chassis_Wheel_Feedback &feedback) const;
```

`valid_mask` 的每一位表示对应电机位置反馈有效；`fresh_mask` 表示相对上一个底盘快照有新 `0x36` 样本。只有四轮均有效、至少存在需要处理的新样本，并且四轮时间偏差在允许范围内时，才进行正常正运动学更新。

四台电机通过 CAN 分时返回，不会拥有完全相同的时间戳。第一版可以使用四轮时间戳最大值作为快照时间，并限制：

```text
max(position_timestamp_us) - min(position_timestamp_us)
    <= max_wheel_skew_us
```

`max_wheel_skew_us` 初始可设为一个位置反馈周期，例如 10 ms，实测总线调度后再收紧。

不要在 `InsTask` 中直接访问 `Class_Chassis` 内部四个 `Class_ZDTMotor` 对象。轮序、减速比、方向和单位转换都应由底盘模块统一处理。

### 6.4 航向融合

第一版使用互补思想融合陀螺仪和轮式旋转增量：

```text
dyaw_gyro = gyro_z * dt
dyaw = alpha * dyaw_gyro + (1 - alpha) * dyaw_wheel
yaw = WrapAngle(yaw + dyaw)
```

初始参数可从以下范围开始：

```text
alpha = 0.95 ~ 0.995
```

解释：

- `alpha` 大：更信任 IMU，短时旋转响应好，但长期受陀螺仪漂移影响；
- `alpha` 小：更信任轮子，容易受打滑和麦轮横向耦合影响；
- 参数必须通过原地旋转和组合运动实测调整；
- 这不是绝对航向校正，轮式里程计本身同样会漂移。

如果确认 VQF Yaw 的零偏处理优于自行积分，也可以使用 VQF Yaw 增量代替 `gyro_z * dt`，但应对 `-pi / +pi` 跳变进行角度差包装。

### 6.5 平移位置积分

将机体系位移旋转到世界系：

```text
dx_world = cos(yaw_mid) * dx_body - sin(yaw_mid) * dy_body
dy_world = sin(yaw_mid) * dx_body + cos(yaw_mid) * dy_body

x += dx_world
y += dy_world
```

推荐使用周期中点航向：

```text
yaw_mid = yaw_previous + 0.5 * dyaw
```

相较于直接使用周期起点或终点航向，中点法在同时平移和旋转时误差更小。

速度可以由本周期位移除以实际时间差得到：

```text
vx_body = dx_body / dt
vy_body = dy_body / dt
```

然后再旋转到世界系。`dt` 必须来自连续反馈的采样时间戳，不能硬编码为 0.01 秒后就完全忽略抖动。

### 6.6 初始化和复位

推荐接口：

```cpp
void Init();
void ResetPose(float x_m, float y_m, float yaw_rad);
Struct_INS_State GetState() const;
```

初始化条件：

1. BMI088 已完成初始化；
2. VQF 输出有效；
3. 四轮反馈均至少成功接收一次；
4. 已保存四轮初始累计角度，避免首次更新出现大位移；
5. 时间戳正常且未过期；
6. 底盘在启动阶段尽量保持静止，使陀螺仪零偏估计稳定。

`ResetPose()` 只重置导航坐标原点，不应清除电机驱动器内部位置，除非调用者明确要求机械回零。

## 7. 位置闭环设计

### 7.1 控制结构

采用三级结构：

```text
轨迹/目标生成
      |
位置和航向外环
      |
vx_body_target / vy_body_target / wz_target
      |
麦轮逆运动学
      |
四轮电机内部速度控制
```

第一版不要从位置误差直接计算四个轮子的 RPM。位置控制与麦轮逆运动学必须分层。

### 7.2 世界系误差转换到机体系

目标误差：

```text
ex_world = target_x - current_x
ey_world = target_y - current_y
eyaw = WrapAngle(target_yaw - current_yaw)
```

转换到底盘机体系：

```text
ex_body =  cos(yaw) * ex_world + sin(yaw) * ey_world
ey_body = -sin(yaw) * ex_world + cos(yaw) * ey_world
```

第一版控制律：

```text
vx_command = kp_x * ex_body
vy_command = kp_y * ey_body
wz_command = kp_yaw * eyaw
```

这里的 `vx_command` 表示向右速度，`vy_command` 表示向前速度。

### 7.3 第一版使用 P 控制

位置外环第一版先使用 P 控制，不急于加入积分项：

- 麦轮受阻或打滑时，积分项容易累积；
- 障碍解除后可能突然输出大速度；
- 静态误差首先应排查轮径、方向、减速比和摩擦问题；
- 加入积分前必须实现输出限幅和抗积分饱和。

如后续需要改善动态响应，可以加入期望速度前馈：

```text
velocity_command = trajectory_velocity_feedforward
                 + Kp * position_error
```

### 7.4 输出限制

控制器必须具备：

- 最大平移速度限制；
- 最大角速度限制；
- 最大平移加速度限制；
- 最大角加速度限制；
- 目标附近减速；
- 位置到达死区；
- 航向到达死区；
- 状态无效时立即停止；
- 电机离线或反馈超时时立即停止；
- 控制任务卡顿或周期异常时立即停止。

二维平移速度推荐按向量模长统一限幅，避免 X/Y 分别限幅后斜向速度变成单轴上限的 `sqrt(2)` 倍：

```text
speed = sqrt(vx^2 + vy^2)
if speed > max_speed:
    scale = max_speed / speed
    vx *= scale
    vy *= scale
```

### 7.5 到达判定

建议同时满足以下条件并持续一定时间才报告到达：

```text
sqrt(ex_world^2 + ey_world^2) < position_tolerance
abs(eyaw) < yaw_tolerance
sqrt(vx_body^2 + vy_body^2) < velocity_tolerance
abs(yaw_rate) < yaw_rate_tolerance
```

避免只根据位置误差判断，否则底盘可能高速穿过目标点时被瞬间判定为到达。

## 8. 任务和数据时序

### 8.1 建议频率

| 模块 | 建议频率 |
|---|---:|
| BMI088 陀螺仪采集和 VQF 更新 | 保持现有约 2 kHz |
| BMI088 加速度更新 | 保持现有约 250 Hz |
| 四轮位置反馈 | 50~100 Hz |
| INS/里程计融合 | 100 Hz 或由完整轮反馈触发 |
| 底盘位置闭环 | 100 Hz |
| 电机速度命令 | 100 Hz 起步，按 ZDT/CAN 能力调整 |

### 8.2 推荐任务职责

`BMI088_Task`：

- 继续处理 BMI088 FIFO；
- 继续执行 VQF；
- 发布带时间戳的最新 IMU 快照；
- 不执行位置闭环。

`InsTask`：

- 等待新的完整轮子反馈或固定 100 Hz 运行；
- 读取同一版本的轮反馈和 IMU 快照；
- 验证时间戳、新鲜度和有效性；
- 计算轮子位移增量；
- 完成航向融合和位姿积分；
- 发布 `Struct_INS_State` 快照。

`Control_Task`：

- 固定周期运行，建议初始为 100 Hz；
- 调用 `Chassis.Process()`；
- 读取最新 INS 状态；
- 执行目标管理、位置/航向控制和限幅；
- 调用 `Chassis.SetVelocity()`；
- 执行超时、安全停止和到达判定。

### 8.3 禁止使用阻塞式运行接口做闭环

现有 `RunForSeconds()` 会在任务中调用 `osDelay()`，适合简单演示，不适合位置闭环。闭环任务应使用：

```cpp
uint32_t next_tick = osKernelGetTickCount();

for (;;)
{
    next_tick += 10U;

    Chassis.Process();
    const Struct_INS_State state = INS.GetState();
    Controller.Update(state);
    Chassis.SetVelocity(vx_command, vy_command, wz_command);

    osDelayUntil(next_tick);
}
```

实际代码应根据 `osKernelGetTickFreq()` 换算周期，不能默认系统 tick 一定是 1 ms。

### 8.4 时间戳要求

- 每个轮子反馈应保留接收时间；
- 完整四轮快照应记录统一发布时刻和各轮数据年龄；
- IMU 快照必须记录其真实采样或解算时间；
- INS 使用输入时间戳计算 `dt`；
- `dt <= 0`、明显过大或时间倒退时拒绝本次积分；
- 数据重复时不得再次积分；
- 任务唤醒标志只能表示“有数据”，不能代替样本队列或序号。

## 9. 接口草案

### 9.1 底盘反馈接口

建议扩展 `Class_Chassis`：

```cpp
struct Struct_Chassis_Wheel_Feedback
{
    int64_t position_raw_signed[CHASSIS_WHEEL_COUNT]{};
    float position_rad[CHASSIS_WHEEL_COUNT]{};
    float velocity_rad_s[CHASSIS_WHEEL_COUNT]{};
    uint64_t position_timestamp_us[CHASSIS_WHEEL_COUNT]{};
    uint32_t position_update_count[CHASSIS_WHEEL_COUNT]{};
    uint64_t snapshot_timestamp_us = 0U;
    uint32_t sequence = 0U;
    uint8_t valid_mask = 0U;
    uint8_t fresh_mask = 0U;
};

class Class_Chassis
{
public:
    bool ConfigureOdometryFeedback(uint16_t period_ms);
    bool StopOdometryFeedback();
    bool GetWheelFeedback(Struct_Chassis_Wheel_Feedback &feedback) const;
    bool IsInitialized() const;

    void SetVelocity(float vx_body_m_s,
                     float vy_body_m_s, 
                     float wz_rad_s);

    void Process();
    void Stop();
};
```

### 9.2 ZDT 手册协议与工程底层调用

本节依据《ZDT_X42S 第二代闭环步进电机用户手册 V1.0.5》以下内容核对：

- 第 42~43 页：CAN 使用经典 CAN 29 位扩展帧，ID 为 `(Addr << 8) | Packet`；
- 第 66 页：`0x11 0x18` 定时返回信息命令；
- 第 71 页：`0x35` 实时转速；
- 第 72 页：`0x36` 实时位置；
- 第 73 页：`0x37` 位置误差与 `0x3A` 电机状态；
- 第 97 页：EMM 系统状态示例进一步确认位置按 `65536` 计数每圈换算。

#### 9.2.1 CAN 帧格式

手册中的串行逻辑命令包含地址字节；转换成 CAN 时，地址和分包号进入扩展 ID：

```text
extended_id = (motor_address << 8) | packet_index
```

每个 CAN 数据包的第一个数据字节仍是功能码。小于等于 8 字节的数据只使用 `Packet=0`；长命令由 `Packet=0,1,...` 分包，每包重复功能码。

工程已实现完整调用链：

```text
Class_ZDTMotor 公共接口
    -> SubmitCommand()
    -> 计算 0x6B / XOR / CRC8
    -> 按 (Addr << 8) | Packet 生成 Classic CAN 扩展帧
    -> CAN_Tx_SubmitBatch()
    -> Can_Tx_Task
    -> BSP_CAN_SendAsync()
    -> HAL_FDCAN_AddMessageToTxFifoQ()
```

长命令用 `CAN_Tx_SubmitBatch()` 一次连续入队，因此不会被其他任务提交的 CAN 帧插入到同一条 ZDT 分包命令中间。

接收链路为：

```text
FDCAN RX FIFO0 中断
    -> HAL_FDCAN_RxFifo0Callback()
    -> 按 (FDCAN, 扩展帧, ID) 匹配回调
    -> Class_ZDTMotor::FeedbackCallback()
    -> CheckResponseChecksum()
    -> ParseFeedback()
    -> Struct_ZDTMotor_Feedback
```

四台电机地址当前配置为 `1,2,3,4`，所以 Packet 0 的接收扩展 ID 分别为：

```text
0x0100, 0x0200, 0x0300, 0x0400
```

`Class_ZDTMotor::Init()` 已为每台电机注册对应 Packet 0 回调。FDCAN2 当前使用 Classic CAN、扩展帧过滤器和自动重发；工程时钟/位时序按当前配置计算为 500 kbit/s，应确保四台电机菜单中的 `CAN_Baud` 同样设置为 500 kbit/s。

#### 9.2.2 配置周期位置反馈

手册命令：

```text
Addr 11 18 InformationFunction PeriodHigh PeriodLow Checksum
```

推荐第一版使用：

```cpp
motor.ConfigurePeriodicFeedback(0x36U, 10U);
```

以地址 1、固定 `0x6B` 校验为例，逻辑命令为：

```text
01 11 18 36 00 0A 6B
```

实际 CAN 帧为：

```text
Extended ID = 0x0100
Data        = 11 18 36 00 0A 6B
```

其中：

- `0x11`：定时返回信息功能码；
- `0x18`：辅助码；
- `0x36`：需要周期返回的实时位置功能码；
- `0x000A`：周期 10 ms，即 100 Hz；
- `0x6B`：当前工程配置的固定校验字节。

停止位置主动返回：

```cpp
motor.ConfigurePeriodicFeedback(0x36U, 0U);
```

手册允许 1 ms 周期，但第一版不应对四台电机都配置 1 ms。建议从 10 ms 开始，检查 CAN 负载、RX FIFO、位置更新计数和丢帧情况后再决定是否提高频率。

建议由 `Class_Chassis` 包装四台电机调用：

```cpp
bool Class_Chassis::ConfigureOdometryFeedback(uint16_t period_ms)
{
    bool ok = true;
    for (uint8_t i = 0U; i < CHASSIS_WHEEL_COUNT; ++i)
    {
        ok = motors[i].ConfigurePeriodicFeedback(0x36U, period_ms) && ok;
    }
    return ok;
}
```

注意：上述函数只表示命令成功进入 CAN 发送队列，不表示四台电机已经开始返回。启动成功必须由各电机的 `position_update_count` 在超时时间内递增来确认。

#### 9.2.3 实时位置返回与现有解析

手册 `0x36` CAN 返回的数据区为：

```text
Byte 0: 0x36
Byte 1: sign，0x00=正，0x01=负
Byte 2..5: 32 位大端位置绝对值
Byte 6: checksum
```

现有 `Class_ZDTMotor::ParseFeedback()` 已解析并写入：

```cpp
Struct_ZDTMotor_Feedback::position_deg
```

为避免长时间运行后两个很大的 `float position_deg` 相减丢失小角度增量，建议解析 `0x36` 时同时保存：

```cpp
int64_t position_raw_signed;
```

返回协议使用独立符号字节和 32 位绝对值，因此需要 `int64_t` 才能完整表示 `-0xFFFFFFFF ~ +0xFFFFFFFF`。里程计优先用原始整数作差，`position_deg` 继续作为调试和普通应用接口。

换算规则：

```text
X 固件：position_deg = raw / 10
EMM 固件：position_deg = raw * 360 / 65536
```

随后由 `ApplyDirection()` 应用 `Init()` 中的 `reverse`，因此上层不应再根据左右轮重复改符号。

手册个别描述写作“0~65535 表示一圈”，而同一手册 EMM 系统状态示例给出 `0x00010000 = 360°`。结合返回字段为 32 位和现有解析，第一版应把 `position_deg` 当作多圈累计角度使用，但必须通过实车测试验证：连续旋转超过一圈时，数值是否连续越过 360°。如果实际固件返回单圈值，再在 `Class_Chassis` 中增加解绕，不能在 INS 中临时猜测。

进入里程计前转换：

```text
EMM:
delta_motor_angle_rad = delta_position_raw * 2 * pi / 65536

X:
delta_motor_angle_rad = delta_position_raw * 0.1 * pi / 180

delta_wheel_angle_rad = delta_motor_angle_rad / gear_ratio
delta_wheel_distance_m = delta_wheel_angle_rad * wheel_radius_m
```

EMM 的 `65536/圈` 是实时位置反馈分辨率；`pulses_per_revolution=3200` 是 EMM 位置控制命令的脉冲换算参数，两者不是同一个量，不能用 3200 去解析 `0x36` 反馈。

如果电机与麦轮直驱，`gear_ratio=1`。

#### 9.2.4 实时转速和状态

实时转速：

```cpp
motor.ReadSpeed();          // 发送 0x35
feedback.speed_rpm;         // EMM 直接为 RPM；X 已除以 10
```

速度换算：

```text
wheel_velocity_m_s = speed_rpm
                   / gear_ratio
                   * 2 * pi * wheel_radius_m
                   / 60
```

实时状态：

```cpp
motor.ReadMotorStatus();    // 发送 0x3A
motor.ReadHomingStatus();   // 发送 0x3B
```

建议上电和故障时使用 `0x3B` 确认：

```text
encoder_ready == true
calibration_ready == true
over_temperature == false
over_current == false
```

运行中低频使用 `0x3A` 监控：

```text
enabled
stall_detected
stall_protected
```

这些状态查询不应与 100 Hz 的四轮位置流混为同一“位置新鲜度”。

#### 9.2.5 当前 ZDT 驱动的已知注意点

1. `GetFeedback()` 能保证单个电机结构体复制一致，但四台电机不是同一硬件采样时刻；聚合层应保存每轮位置时间戳，并限制四轮最大时间偏差；
2. `online` 只表示收到任意合法反馈，不能代替 `position_timestamp_us`；
3. `ConfigurePeriodicFeedback()` 不限制 `function`，应用层只应传入手册 5.5 支持的读取功能码；
4. 固定 `0x6B`、XOR、CRC8 必须与电机菜单一致，否则只会增长 `checksum_error_count`；
5. `firmware` 必须与 `ReadOptionStatus()` 得到的 `reported_firmware` 一致，否则 `0x35/0x36` 量纲解析错误；
6. 现有 `0x39` 温度符号解析与手册相反：手册定义 `00=负、01=正`，当前代码按非零取负。第一版若使用数值温度做保护，应先修正；目前 `0x3B` 的过热状态位仍可用于保护；
7. `Class_Chassis::Init()` 当前忽略四个 `motors[i].Init()` 的返回值，后续应改为返回 `bool`，回调注册失败时禁止进入闭环；
8. `SetVelocity()` 当前忽略 `SetSpeed()` 和同步触发返回值，闭环版本应汇总执行结果并在提交失败时进入安全停止；
9. 现有 CAN 回调容量为 16，四个 ZDT 实例会占用 4 个槽，当前容量足够，但增加更多设备时需要重新核算。

### 9.5 第一版推荐调用顺序

#### 上电初始化

```text
MX_FDCAN2_Init()
    -> osKernelInitialize()
    -> BSP_CAN_ConfigInit()，创建发送队列并启动 FDCAN
    -> 创建 Can_Tx_Task / BMI088_Task / InsTask / Control_Task
    -> Control_Task 中调用 Chassis.Init()
    -> 四次 Class_ZDTMotor::Init()
    -> 四次 BSP_CAN_RegisterCallbackEx()
```

底盘初始化后，对每台电机依次执行：

```cpp
motor.ReadVersion();
motor.ReadOptionStatus();
motor.ReadHomingStatus();
```

只有以下条件全部成立才允许使能闭环：

```text
online == true
reported_firmware == configured_firmware
encoder_ready == true
calibration_ready == true
over_temperature == false
over_current == false
```

随后：

```cpp
Chassis.ConfigureOdometryFeedback(10U); // 四轮 0x36，初始 100 Hz
Chassis.Enable();                       // 四轮缓存使能后广播同步触发
```

必须等待四轮各自收到至少一帧新的 `0x36`，把它们保存为初始基准角度，然后才能把 INS 状态置为有效。第一次反馈只建立基准，不产生位移。

#### INS 固定周期

第一版可将 `InsTask` 改为 100 Hz 周期任务：

```cpp
for (;;)
{
    next_tick += ins_period_ticks;

    Struct_Chassis_Wheel_Feedback wheel{};
    if (Chassis.GetWheelFeedback(wheel))
    {
        const Struct_INS_IMU_Sample imu = GetIMUSnapshot();
        INS.Update(wheel, imu);
    }

    osDelayUntil(next_tick);
}
```

`INS.Update()` 必须使用位置更新序号去重。若一个周期内只有部分车轮收到新反馈，第一版建议等待四轮组成完整的新快照；不要把旧轮位置和新轮位置无条件混合后重复积分。

#### 控制固定周期

`Control_Task` 同样以 100 Hz 周期运行：

```cpp
Chassis.Process();
state = INS.GetState();

if (!state.valid || !ChassisFeedbackHealthy())
{
    Chassis.Stop();
}
else
{
    command = Controller.Update(state, dt_s);
    Chassis.SetVelocity(command.vx_body_m_s,
                        command.vy_body_m_s,
                        command.wz_rad_s);
}
```

闭环期间不再调用 `RunForSeconds()`。

#### 停止与退出

正常退出或故障时：

```cpp
Chassis.Stop();
Chassis.StopOdometryFeedback(); // 内部对四台电机发送 0x11 0x18 0x36 0x0000
```

是否随后 `Disable()` 取决于机械是否需要保持力矩。急停策略必须结合实际机械风险决定，不能默认“失能松轴”总是更安全。

## 10. 数据有效性和安全策略

### 10.1 轮子反馈有效性

以下任一情况出现时，不应继续正常积分：

- 任一车轮离线；
- 任一车轮反馈超时；
- 四轮反馈时间差超过阈值；
- 位置增量超过物理上限；
- 时间戳不递增；
- 电机报告堵转、过流、过温或保护；
- 反馈校验错误连续出现。

在定位输入暂时失效时，可短时间保持最后速度估计用于平滑，但控制输出应尽快降为零；第一版建议直接安全停止，降低系统复杂度。

### 10.2 IMU 有效性

以下情况应将 IMU 判为异常：

- BMI088/VQF 重置计数增加；
- 时间戳异常计数增加；
- 加速度或角速度出现非有限值；
- IMU 数据超过新鲜度阈值；
- 陀螺仪样本间隔明显异常；
- 姿态矩阵或四元数无效。

IMU 短时失效时，可以仅用轮式 `dyaw_wheel` 更新，但应记录降级状态并限制最大速度。

### 10.3 控制安全

以下情况必须停止底盘：

- INS 状态无效；
- 控制周期超时；
- 任一关键电机离线；
- 目标或计算结果为 NaN/Inf；
- 输出超出合理物理范围；
- 外部急停或任务故障；
- 初始化未完成。

停止时优先调用四轮同步停止，避免只停止部分车轮导致底盘突然旋转。

## 11. 第一版打滑处理

第一版不需要立刻实现复杂打滑估计，但必须预留检测标志和降级策略。

### 11.1 角速度残差

```text
residual_wz = abs(wz_wheel - gyro_z)
```

残差持续超过阈值时，可能存在：

- 车轮打滑；
- 轮径或 `R` 参数错误；
- IMU 和底盘坐标轴符号错误；
- 轮反馈时间不同步；
- 陀螺仪偏置或异常。

不能仅凭单帧残差认定打滑。

### 11.2 加速度残差

轮式速度差分得到预测加速度：

```text
ax_wheel = (vx_body_now - vx_body_previous) / dt
ay_wheel = (vy_body_now - vy_body_previous) / dt
```

与低通后的 IMU 线加速度比较：

```text
residual_a = norm(a_wheel - a_imu_body)
```

加速度计容易受麦轮滚子振动和冲击影响，所以需要：

- 低通滤波；
- 连续多帧超阈值；
- 排除碰撞和跳变；
- 结合角速度残差和电机状态共同判断。

### 11.3 第一版降级策略

检测到疑似打滑时：

- 设置 `wheel_slip = true`；
- 限制平移速度与加速度；
- 降低对轮式旋转增量的权重；
- 记录调试数据；
- 严重或持续打滑时停止底盘。

不要在没有绝对位置观测时完全相信 IMU 平移积分来替代轮式位置，否则通常会产生更大误差。

## 12. 参数标定

### 12.1 车轮等效半径

1. 让四轮执行相同的累计角度；
2. 测量底盘直线实际位移；
3. 根据理论位移与实际位移比例修正轮半径；
4. 正向和反向分别测试；
5. 多次取平均。

麦轮的等效半径可能与标称外径不同，应使用实车结果。

### 12.2 旋转几何参数

原地旋转若干圈，比较：

- 轮式里程计计算的角度；
- IMU 计算的角度；
- 人工或外部基准测得的实际角度。

据此标定有效旋转半径 `R_effective`。实际有效值可能不完全等于机械测量的 `half_length + half_width`。

### 12.3 横移比例

麦轮横移滑移通常大于纵向运动。可在第一版后期加入独立比例：

```text
dx_body_corrected = k_lateral * dx_body
dy_body_corrected = k_longitudinal * dy_body
```

但在坐标、极性、轮径和时间戳尚未验证前，不应使用经验比例掩盖基础错误。

### 12.4 IMU 零点和安装

- 启动时静置，检查 `gyro_z` 平均值；
- 检查静止时去重力加速度是否接近零；
- 向右、向前和逆时针运动，检查轴符号；
- 倾斜底盘检查 Roll/Pitch 方向；
- 确认加热器启用状态与加速度/陀螺仪标定参数是否匹配。

## 13. 推荐实现顺序

严格按以下顺序实现和验收，不要一开始同时调定位、融合和位置 PID。

### 阶段 1：统一单位和底盘参数

- 增加轮半径和减速比；
- 明确 `SetVelocity()` 使用 `m/s`、`rad/s`；
- 正确计算 `speed_to_motor`；
- 验证四轮极性和轮序。

验收：分别发出纯向右、纯向前和纯逆时针命令，四轮方向符合运动学定义。

### 阶段 2：取得可靠的四轮反馈

- 配置位置周期反馈；
- 封装完整四轮反馈快照；
- 增加序号、时间戳、有效掩码和超时；
- 确认位置是否回绕；
- 确认反馈方向已经应用电机极性。

验收：手动转动单个轮子，仅对应轮子的累计角度按预期方向变化。

### 阶段 3：纯轮式里程计

- 实现位移增量计算；
- 实现麦轮正运动学；
- 暂时只使用 `dyaw_wheel`；
- 输出并绘制 `x / y / yaw`。

验收：完成直线、横移、原地旋转和矩形路线测试，方向和量级正确。

### 阶段 4：接入 IMU 航向

- 发布一致的 IMU 快照；
- 验证机体系轴映射；
- 使用 `gyro_z` 或 VQF Yaw 增量；
- 实现互补融合；
- 处理角度包装和时间异常。

验收：原地旋转和边走边转时航向连续，无 `2*pi` 跳变，停止后漂移速度可接受。

### 阶段 5：位置闭环

- 新建位置控制器；
- 将世界系位置误差转换到机体系；
- 首先使用 P 控制；
- 加入速度、加速度和角速度限制；
- 实现到达判定和异常停止。

验收：低速执行单轴目标，再执行组合目标；误差收敛，目标附近无明显振荡。

### 阶段 6：标定和打滑检测

- 标定轮径、旋转半径和横移比例；
- 记录轮式与 IMU 残差；
- 加入持续多帧的打滑判定；
- 增加打滑时降速或停止策略。

验收：不同速度和方向下误差可重复；轻微打滑不会立即引发错误动作，严重打滑能进入降级状态。

## 16. 常见错误

1. 直接对 `Get_Accel()` 二次积分并把结果作为唯一位置反馈；
2. 对 `Get_Accel_Body()` 再减一次重力；
3. 将 RPM、轮角速度和轮缘线速度混用；
4. 将度和弧度混用；
5. 用固定任务周期代替传感器时间戳；
6. 多次收到同一反馈时重复积分；
7. 四个轮子反馈不在同一时间附近仍直接做正运动学；
8. 忽略电机极性、轮序和麦轮滚子安装方向；
9. 使用位置 PID 直接输出四轮速度而跳过底盘速度层；
10. 一开始加入较大积分项，掩盖机械参数和单位错误；
11. 使用 `RunForSeconds()` 的阻塞流程实现闭环；
12. 只判断位置误差，不判断当前速度就报告到达；
13. 发生打滑时完全改用 IMU 平移双积分；
14. 把 VQF Yaw 当作长期无漂移的绝对航向；
15. 没有状态有效标志和超时保护仍继续下发速度。

5. 已发布一致、带序号和有效标志的 INS 状态快照；
6. 已将 `Control_Task` 改造成非阻塞固定周期闭环；
7. 已实现位置/航向外环、限速、限加速度和到达判定；
8. 任一关键数据失效时能够安全停止；
9. 已完成前进、横移、旋转、组合移动和闭环到点测试；
10. 关键输入、中间状态和输出均可遥测、记录和复现；
11. 已记录轮径、旋转半径、横移比例和控制参数的标定值；
12. 已明确第一版的实测误差和适用边界。

第一版的核心评价标准是“链路正确、行为可解释、异常可停止、误差可测量”，而不是依靠复杂滤波器在基础参数尚未验证时获得表面平滑的数据。

## 19. 实现前需要用户补充或确认的数据

以下信息不能从当前源码或电机手册中可靠推断。收到这些数据后，才能确定最终接口参数、运动学换算和闭环限值。

### 19.1 必须提供的机械参数

1. 麦轮标称直径和实测有效直径，单位 mm；
2. 底盘中心到前/后轮轴中心的距离 `half_length`，单位 mm；
3. 底盘中心到左/右轮接触中心的距离 `half_width`，单位 mm；
4. X42S 电机是否与麦轮直驱；如果不是，请提供“电机转数 / 车轮转数”的减速比；
5. 四个麦轮滚子安装方向，以及左前、右前、左后、右后与电机地址 1~4 的对应关系；
6. 轮子在悬空和落地时是否会发生机械打滑、联轴器回差或明显弹性变形。

### 19.2 必须确认的电机和 CAN 参数

请确认四台电机当前菜单实际值，而不只依据代码默认值：

```text
固件：EMM 还是 X
CAN_Baud：是否为 500 kbit/s
地址：是否依次为 1、2、3、4
校验：固定 0x6B、XOR 还是 CRC8
P_Serial / 通讯端口复用：是否已经设为 CAN
控制命令应答：当前选项值
```

还需要一次台架反馈测试结果：

1. 手动或低速驱动单台电机连续转动 3 圈；
2. 记录每圈附近 `GetFeedback().position_deg`；
3. 确认它是 `0 -> 360 -> 720 -> 1080` 连续累计，还是每圈回绕；
4. 断电重启后确认位置是否归零、保持，或取决于掉电记录电池；
5. 确认 `reverse=true` 的右侧电机反馈正方向与底盘正运动学一致。

### 19.3 必须提供的 IMU 安装关系

1. 主控板在底盘上的朝向；
2. BMI088 X/Y/Z 正方向分别对应底盘的右、前、上中的哪一个方向；
3. BMI088 到底盘旋转中心的平面偏置，单位 mm；
4. 底盘工作时是否基本水平，是否需要在坡面运行；
5. 是否启用 BMI088 加热器，以及当前加速度计/陀螺仪标定参数是否为该块板实测结果。

如果 IMU 不在旋转中心，快速旋转时加速度中会包含杆臂向心和切向分量。第一版平移位置主用轮式里程计，影响有限；后续把加速度加入 EKF/打滑检测时必须使用该偏置补偿。

### 19.4 必须提供的控制指标

1. 最大前后速度、最大横移速度，单位 `m/s`；
2. 最大旋转速度，单位 `rad/s` 或 `deg/s`，需注明单位；
3. 允许的最大平移/旋转加速度；
4. 典型单次移动距离和最长连续运行时间；
5. 期望到点精度，例如位置误差多少 mm、航向误差多少度；
6. 目标地面材质，以及是否存在坡面、地毯、接缝或容易打滑的区域；
7. 故障时希望“锁轴保持”还是“失能松轴”；
8. 是否已有急停输入，以及急停接口位于哪个 GPIO/CAN/上位机命令。

### 19.5 可选但会显著改善长期精度的外部观测

请说明是否计划接入以下任一种接口，并提供数据格式、频率、时间戳来源和坐标系：

- 相机/AprilTag 位姿；
- UWB 二维或三维位置；
- 激光雷达里程计或定位；
- 地面光流速度；
- 室外 GNSS/RTK；
- 上位机视觉提供的绝对位置或航向。

外部观测至少应包含：

```text
measurement value
measurement timestamp
coordinate frame
valid/quality flag
estimated uncertainty or confidence
```
